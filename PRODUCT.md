# Product

## Register

product

## Users

antiWG serves two groups: student users who want a low-friction way to manage school check-in automation, and administrators who need to operate accounts, proxy routing, tokens, dorm data, notices, and failure diagnostics. Users usually arrive with a concrete task in mind, often on a phone or a remote server session, and need clear state, trustworthy feedback, and fast recovery paths.

## Product Purpose

The product automates and monitors late-return school check-ins while keeping per-user settings, token refresh, notification channels, proxy routing, and admin operations understandable. Success means users can confirm their account is configured correctly, understand whether sign-in will happen, and troubleshoot failures without guessing; admins can see system health and adjust configuration without touching server internals for routine work.

## Brand Personality

Calm, precise, reliable. The interface should feel like a quiet operational console: sparse, direct, and technically confident, with enough warmth to keep stressful maintenance tasks approachable.

## Anti-references

Avoid loud dashboard tropes, oversized red surfaces, glassmorphism as decoration, busy gradients, marketing-page composition, and novelty UI that makes operational tasks harder to scan. Do not make the app look like a generic SaaS landing page, a game UI, or a heavy cyberpunk admin panel.

## Design Principles

- Clarity before decoration: every screen should make the current state and next safe action obvious.
- Quiet confidence: use restraint, whitespace, and crisp hierarchy so users trust the tool during failures.
- Diagnose in place: surface relevant technical details near the workflow that needs them, with expansion for full records.
- Per-user boundaries: visual language should reinforce that user proxy, token, and sign-in settings are scoped and not accidentally shared.
- Mobile-operable: common user tasks must remain comfortable on small screens, not only desktop dashboards.

## Accessibility & Inclusion

Target WCAG AA contrast for text and controls. Preserve keyboard focus states, avoid color-only status communication, keep touch targets at least 44px where possible, respect reduced-motion preferences, and make dense diagnostic text readable through spacing and line-height rather than shrinking it too far.
